# Myla 的一天（Scriptable 版）

配色是糖果色：明度 54~68%、饱和 36~95%。第一版明度推到 80% 结果看着像掉色——
HSL 里明度越接近白，能达到的彩度上限越低，所以「又亮又艳」得把明度压回 60% 上下
再拉饱和度。十个状态在圆环上首尾相接，选色时逐对检查过色相差、明度差和饱和度差，
没有会看混的组合。

不用 Xcode、不用 iCloud、不用开发者账号、不会 7 天过期。只要手机上装一个免费 app。

圆盘、小组件、地点自动切换、定时提醒——四样都有。

**Clawd 会跟着当前状态换动作**：睡觉闭眼冒 Zzz、科研抱电脑、学习抱书、吃饭端碗、
通勤背包、运动举哑铃、休息端杯子、刷手机低头看屏幕、上课举手。它自己的橙色（`#E88E68`）不变，换的是姿势和道具。想换深浅改 `drawClawd` 里的 `HEX` 一处即可。圆盘和小组件共用同一份绘制代码，所以小组件上同步能看到。

界面在 WebView 里，是真的 HTML/CSS——卡片、字体层次、iOS 那种分段控件、底部 tab、
从下面滑上来的详情页。之前用 Scriptable 的 `UITable` 做，那玩意儿只能一行一行摆文字，
再怎么调都是系统设置页的长相。

```
MylaCore.js    数据读写 + 圆盘/占比环/倒数日绘制 + Clawd（app 和小组件共用，只有一份实现）
MylaView.js    视图层，纯 HTML/CSS，一行业务逻辑都没有
Myla.js        控制器：组装数据 + 存盘 + 自己更新自己
MylaWidget.js  主屏小组件
MylaWhy.js     记录不对劲的时候跑它，把真实数据摊开看
```

> 文件名从 `MylaDay*` 换成了 `Myla*`。原因不体面：用户那边更新怎么都不生效，
> 而我查不出为什么。换一套全新文件名可以一次性绕开所有我看不见的东西——
> 旧文件的模块缓存、可能存在的重复副本、本机和 iCloud 目录不一致。
> 数据文件名没变（`myladay.json`），所以记录照常在。

**页面自己就是完整的 app。** 数据在 `loadHTML` 之前就写进页面，所有点击在页面内直接生效，
窗口开着的时候脚本完全不参与。

第一版不是这么做的，栽了：往**已经弹出来的** WebView 里 `evaluateJavaScript` 送数据送不到，
所以 `render` 从没跑过（白屏），而脚本还在等一条永远不会来的消息（一直转圈）。
`present()` 兑现**之后**再读页面变量是可靠的，所以改成关窗口时一次性回放。

存盘走**两条通道**，因为单靠任何一条我都验不了：

- **主通道**：页面每做一件事就发起一次 `myladay://` 跳转，脚本在 `shouldAllowRequest`
  里拦下来、落盘、拒绝导航。WebView 弹出来之后，这是唯一能实时把东西送出去的地方。
- **兜底**：关掉窗口后脚本再读一遍页面记的 `window.LOG`。

两边都按操作序号 `i` 去重，所以「只有主通道通」「只有兜底通」「主通道通一半就断」
三种情况结果完全一致，不会漏也不会重复（实测过）。

一开始只有兜底那条，而它是我验不了的路径——如果它不工作，用户所有操作都白点，
状态会一直停在之前那个，看起来就是「怎么点都还是休息」。所以补了主通道。

每条操作**带自己发生的时间戳**，
所以「14:00 切成学习、14:30 才关窗口」记下来仍然是 14:00，晚存不影响准确性。
唯一的丢失场景是窗口开着时把 Scriptable 强杀。

代价是 24 小时圆环在页面里用 SVG 又画了一遍（脚本那份给小组件用）。圆环几何很简单
——每段就是一天里的起止比例——但这确实是两份实现，改配色要两边都改。
Clawd 仍然是脚本画的，按状态预生成成图片传过去。柱状图和占比环页面直接用 div 和 SVG 画。

## 三个页面

**今天**（打开就是）：24 小时圆盘 → 切状态 → 今天的清单 → 别的。

**统计**（「别的」里进）：两排切换器，上面一排选时间粒度 `周 / 月 / 3个月`，
下面一排选图形 `柱状 / 圆盘`。柱状是每天一根的堆叠柱，3个月自动收成一周一根——
90 根柱子每根两像素，看不出任何东西。圆盘是这段时间的占比（跟首页那个不一样，
首页是时间轴，这个是比例）。下面的事项列表点进去是单项详情。

选的粒度和图形会记住，下次打开还是你上次看的那个。

**单项详情**：这个状态在选定时间里的柱状图、总计、有记录的天平均、出现过几天、
最长的一次是哪天几点，以及今天的具体时段（点一段能拆开）。

刻意**没做**「平均每天几小时」这个总览指标——这个 app 的模型是「永远有一个状态在跑」，
每天总和必然接近 24 小时，平均下来永远是 24，是句废话。单项的平均才有意义。

## 倒数日

「别的 → 倒数日」记重要的日子，显示在**大号小组件右边**。生日纪念日这种打开「每年重复」，
过完自动滚到明年。已经过去的日子排在最后、数字小一号也暗一点。

按「天」算不按 24 小时算——今晚 23:00 到明早 8:00 是「明天」，不是「还有 9 小时」。

右侧那块是用 `DrawContext` 画成一张图再放进小组件的，不是用 ListWidget 的堆栈拼的。
理由很实际：画成图我才能在电脑上渲染出来核对排版，堆栈布局只有装到手机上才知道长什么样。

小组件三个尺寸：小号只有圆盘，中号圆盘 + 最近一个倒数日 + 时长，大号左边圆盘和时长、
右边五个倒数日。

## 今天要做的（清单）

打勾就完事，不弹窗不追问。**做完的不消失**，沉到底下并记下打勾的时间——
一天结束时能看见自己干了什么，比清空列表有用。

昨天没做完的会问一句「搬过来？」，**不自动搬**。

刻意**没做**「开始这条任务」把清单和圆盘绑在一起：清单是打算做的，圆盘记的是
真的在做的，两件事不该互相替对方做决定。同理，勾完一条不会自动切状态。

清单和时间记录在同一个文件里，备份、恢复、导出都是一起走的。

## 上划退出 app 会怎样

上划退出是**直接杀进程**，所以「关窗口之后」才跑的东西一概不会执行。
四条存盘通道里只有前两条（点击时拦截、开着时每两秒轮询）能救，后两条
（pagehide、关窗口后再读）指望不上。设计上就是按这个来的：前两条任意一条通，
数据就都在；实测「上划杀掉」之后磁盘上东西一条不少。

同样的道理，**自动更新原来放在关窗口之后，对上划退出的人永远不会跑**——
所以更新一直不生效。现在搬到了打开 app 之前，最多六小时查一次，静默下载，
下次打开生效，不弹窗不打断。

## 更新：app 自己会更新

正常用就行。**关掉窗口之后**它会对一下 GitHub 上的最新 commit，有新的就下好，
下次打开就是新的，并且弹一句告诉你从哪一版到哪一版。每小时最多查一次，
「别的 → 检查更新」可以立刻查。

放在关窗口之后是有意的：一点都不占打开 app 的时间。

正在跑的那份代码已经在内存里了，覆盖文件不影响当前这次运行——所以是「下次打开生效」，
不是「立刻变」。

下载钉在具体 commit 上，不用分支名。分支名在 jsDelivr 上能陈到几小时前，
只要 GitHub 那边超时一次回落过去，就会静默装回一份旧代码而且看起来一切正常——踩过。
没下全就不记 sha，下次接着试，不会留下一半新一半旧。

只覆盖脚本，`myladay*.json` 一律不碰。

`install.js` 现在只用来**第一次**把东西装上，之后就用不到了。

## 装

**1. 手机上装 [Scriptable](https://apps.apple.com/us/app/scriptable/id1405459188)**（App Store 免费）。

**2. 新建一个脚本，把 `install.js` 的内容粘进去，跑一次。**

三个正式脚本就下到本地了。以后我改了代码，你再跑一次 `install` 就是更新。

（不想粘的话，AirDrop 过去 `.js` 文件、在分享菜单里选 Scriptable 也行，但这条我没法替你验证。）

**3. 放个主屏幕图标**（不用每次先开 Scriptable）：

1. 「快捷指令」→ ＋ → 搜 **打开 URL**
2. 填 `scriptable:///run?scriptName=MylaDay`
3. 快捷指令命名为 **Myla 的一天** → 保存
4. 在快捷指令列表里长按它 → **分享** → **添加到主屏幕** → 点图标换成下面那张 Clawd 图

`icon.png` 在这个目录里，先存到相册。

**4. 加小组件**：长按主屏 → ＋ → Scriptable → 选小号或中号 → 编辑小组件 → Script 选 `MylaDayWidget`。

数据存在 Scriptable 自己的目录里（`myladay.json`），主脚本和小组件读同一个文件，**所以没有原生版那个 App Groups 的坑**。

## 地点自动切换（在「快捷指令」里配）

Scriptable 自己不能在后台监听围栏，但系统的快捷指令可以，触发之后调用脚本：

1. 打开**快捷指令** → 底部**自动化** → ＋ → **到达**
2. 选地点（比如实验室），选「**立即运行**」，把「运行前询问」关掉
3. 动作里搜 **Run Script**（Scriptable 的动作），Script 选 `MylaDay`
4. 展开动作，**Parameter** 填状态名，比如 `科研`（填 id `research` 也认）

离开时切成别的，就再建一条「**离开**」的自动化。每个地点一条，家、学校、实验室、健身房各配一次，配完就不用管了。

主脚本收到参数会**直接切状态然后退出，不弹界面**，所以自动化触发时你根本不会被打断。

## 自动切换：手动优先

地理围栏会**反复触发**——在围栏边上走两步就是一次进出。原来没有任何保护，
于是「你手动设成学习 → 围栏触发休息 → 学习那段当场被截断」，一天下来全是休息，
学习一分钟都没记上。这是真实踩到的。

现在每一段都记着是谁切的（`by: "me" | "auto"`）。**你亲手设的状态，保护期内自动化不许改**，
默认 30 分钟，可以在「别的 → 自动切换」调，也能完全关掉自动切换。
被跳过的时候首页会明说「自动化想切成休息，你 8 分钟前刚手动设成学习，没动它」——
不静默，你才知道自动化在后面干什么。

通知按钮不算自动——那是你自己按的，直接生效。

老数据里没有 `by` 字段的段一律当成手动，方向偏保守（宁可拦住自动化，不可覆盖你的记录）。

要是记岔了：**统计 → 点那个状态 → 点某一段 → 整段改成别的状态**。
自动化切出来的段在列表里标着「自动」。

## 定时问一句

主脚本里「提醒」那行可以设间隔（默认 90 分钟，可关）。超过这个时长没换状态，就推一条通知：

> **还在学习吗？**
> 已经 1 小时 50 分。点一下确认或者改掉，圆盘就不会记错。
> 　[ 改成科研 ]　[ 改成休息 ]

按钮直接在通知上，点了就切，**不用打开 app**。旁边那两个是你今天用得最多的另外两个状态。每次切换（手动或自动）都会把下次问话往后推。

> 通知按钮走的是 `scriptable:///run?scriptName=MylaDay&switchTo=xxx` 这个 URL。这条我没法在电脑上验证，
> 万一按钮没反应，就是这个 URL 形式的问题，告诉我我换成 `scriptable:///run/MylaDay?...`。

## 睡觉那一段

睡着之后没人能替你点，所以早上起来那一大段一定是错的。主界面会主动提示：

> ✂︎ 这一段已经 9 小时 12 分，中间换过吗？

点开输入几点睡的、选后半段是「睡觉」，一刀切成两段。

刻意**没做**「到点自动切成睡觉」——那是系统替你猜，猜错了圆盘就不可信。拆分是你说边界在哪。

## 数据不会因为更新丢

脚本和数据是**分开的两组文件**，更新只覆盖 `.js`，`myladay*.json` 一律不碰。
安装脚本跑完的弹窗里会把你的记录文件列出来，确认没被动过。

写入是「先写临时文件 → 读回来核对长度 → 把现有的存成备份 → 才替换正式文件」，
所以中途崩溃时正式文件仍然是上一份完整的。读取时如果 JSON 解析失败，
**不会静默清空**：坏文件改名成 `myladay.corrupt-<时间戳>.json` 留档，然后用
`myladay.backup.json` 恢复，界面上会显示一条橙色提示告诉你发生了什么。
最坏情况（主文件和备份都坏）才回到空白，并且界面上会用红字说明。

五种情况都用 Node 打桩实测过：首次使用、正常存取、产生备份、主文件写坏、
主文件和备份都没了。备份是「上一次保存」，所以最多丢最后一次改动。

数据结构带版本号 `v`，`migrate()` 负责把老结构补齐字段，以后改格式不会把旧记录搞丢。

主脚本「别的」里有**导出一份备份**，存到「文件」App，换手机或者我改坏了都能拿回来。
迭代频繁的话建议偶尔导一次。

## 改完跑 check.sh

```bash
./check.sh
```

盯五件踩过的坑：

1. **顶层 `await`** —— Scriptable 允许，Node 的 CommonJS 不允许，所以按模块语义查。
2. **页面里的 JS** —— 它被包在模板字符串里，对外层文件来说只是一段普通字符串，
   `node --check MylaDayHTML.js` **根本看不见它**。里面写错照样「通过」，装到手机上就是白屏。
   必须单独抠出来查。这个漏洞真的放过了一次白屏。
3. **模板字符串吞掉的单反斜杠** —— `\d` 写成 `\d` 不报错，但正则会变成匹配字母 d，
   功能静默失效。
4. **正则字面量里的 U+2028/2029** —— 它俩本身就是换行符，写进去当场断行。
5. **定义了却没人调的函数** —— 倒数日、自动切换、检查更新三个入口都出现过
   「函数写好了但没接进界面」：语法全对，跑测试也过，因为我测的时候是直接调函数，
   没从界面点进去。这条按整个页面数引用次数（导航栏的 onclick 写在静态 HTML 上，
   只数 `<script>` 里面会误报）。

## 已经验证 / 没验证的

**验证过**：把 Scriptable 的 `DrawContext`、`Path`、`Color` 这些 API 用 Node 打了桩，
**跑真实的 `drawDial` 和 `drawClawd` 代码**输出 SVG 再转成图看——圆环角度、刻度、"现在"那条线、
Clawd 的比例都对。四个文件 `node --check` 语法全过。第一版 Clawd 画太大顶到圆环了，就是这么发现的。

**这一版验证过的**：把真实 payload 喂给真实 HTML，在浏览器里按 iPhone 尺寸点了一遍——
切状态（圆环、Clawd、时长立刻跟着变）、打勾、加条目、周/月/3个月（7/30/13 根柱子）、
柱状↔圆盘、单项详情、拆分选时间选状态。然后把浏览器里**实际点出来的那串操作**导出来，
喂给脚本里真实的 `apply()` 回放，核对结果：段首尾相接不留空档、拆分位置对、
切状态用的是当时点的时间而不是关窗口的时间。

**没验证**：Scriptable 特有的东西一概没跑过——`UITable` 的排版、`Notification` 的按钮 URL、
`importModule`、快捷指令传参。这些只有在你手机上才知道。出错的话 Scriptable 会直接显示行号，
截图发我就行，改一行重跑，不用编译。

## Scriptable 版和原生版的取舍

仓库里 `ios/` 是完整的 SwiftUI 原生版，功能一样。两条路都留着：

| | Scriptable | 原生（`ios/`） |
|---|---|---|
| 电脑要装 | 什么都不用 | Xcode 约 20G |
| 账号 | 不需要 | 免费的 7 天过期，小组件还要付费才能开 App Groups |
| 界面 | UITable，朴素 | SwiftUI，随便做 |
| 地点触发 | 快捷指令里每个地点配一次 | app 内置，装好就工作 |
| 屏幕使用时间 | 拿不到 | 能嵌 Apple 的报告视图（也只能看不能算）|
